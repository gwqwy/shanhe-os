# 山河 Linux · 构建指南

## 前置要求

| 项 | 要求 |
|---|---|
| 构建机 | Debian 13 或 Ubuntu 24.04+（虚拟机即可），x86_64 |
| 权限 | root（sudo） |
| 网络 | 需联网下载约 3~4 GB 软件包 |
| 磁盘 | 至少 15 GB 空闲 |
| 时间 | 20~40 分钟（视网速与 CPU） |

> 构建机可以是：另一台 Linux 虚拟机、WSL2（需 systemd）、或任意 Linux 服务器。
> 不要在要运行 ISO 的同一台 VMware 虚拟机里同时构建（内存与磁盘压力大）。

## GitHub Actions 云端构建（推荐，无需本地 Linux）

仓库已内置 CI 工作流 `.github/workflows/build-iso.yml`，三种用法：

1. **推 main 自动构建**：向 `main` 分支推送即自动构建（仅构建，不发 Release）。
   构建完成后在该次运行页面的 **Artifacts** 里下载分卷 ISO 与构建日志。
2. **手动触发**：GitHub 仓库 → Actions → 「构建山河Linux ISO」→ Run workflow。
   同样只构建，产物在 **Artifacts** 里下载。
3. **自动发布**：推送 `v*` 标签即自动构建并创建 Release：
   ```bash
   git tag v0.3.0 && git push origin v0.3.0
   ```
   Release 会附带自动分卷的 ISO（1900MB/卷）、SHA256SUMS 与合并命令说明。

> **触发规则**：`branches` 与 `tags` 需同时声明，GitHub 才会「命中任一即触发」——
> 只写 `tags` 则分支推送不触发，只写 `branches` 则标签推送不触发。
> 因此推 main 只构建、不发布 Release（发布步骤有 `refs/tags/v` 守卫）。
>
> **并发控制**：同一分支/标签仅保留最新一次构建，新推送会取消该分支上跑着的旧构建；
> 标签构建自成一组，不会被分支推送取消。

CI 说明：运行器磁盘紧张，工作流已内置空间清理；CI 用 Debian 官方源（机房直连更快，
通过 `SHANHE_MIRROR` 环境变量覆盖本地默认的 TUNA）；`live/cache` 走 actions/cache
增量加速。**公开仓库 Actions 免费**；私有仓库按分钟计费但单次构建（约 30~60 分钟）额度充足。
Limit：Actions 只能"构建"ISO，不能运行图形界面做自动化测试。

## 一键构建

```bash
cd shanhe-os
sudo bash build.sh
```

产物：`山河Linux-0.3.0-amd64.iso`

变体：

```bash
sudo bash build.sh --no-di     # 不带"安装到硬盘"引导项（纯体验版，体积略小）
```

## 常见构建问题

| 问题 | 原因 / 处理 |
|---|---|
| `lb: command not found` | 依赖安装失败，手动 `apt install live-build rsync curl` |
| Ubuntu 上报 `未识别的选项 "--image-name"` | Ubuntu 自带 live-build 是 3.0 老分支——新版 build.sh 会检测并自动换装 Debian 官方版，请使用最新的 build.sh 重跑 |
| 报 `Cannot check Release signature` | Ubuntu 缺 Debian 签名密钥——新版 build.sh 会自动安装 debian-archive-keyring |
| **下载只有几 KB/s** | 已默认使用清华 TUNA 镜像（`live/auto/config` 里 5 个 mirror 参数）；海外机器可在该文件中换回 deb.debian.org |
| 下载 404 / hash 校验失败 | 镜像同步中，稍后重跑（lb 有缓存，不必从头来） |
| 钩子 0010 报 Go 编译错误 | 检查 vendor/sahou 完整性；可删除后 `git clone --depth 1 https://github.com/gwqwy/sahou vendor/sahou` |
| ISO 很大（>4GB） | 正常：KDE + Wine + 固件全在里面 |
| 想重构建 | 直接再跑 `sudo bash build.sh`（缓存会复用，第二次快很多） |

## 构建过程发生了什么

1. **依赖**：安装 live-build 全家桶。
2. **源码布置**：`vendor/sahou`（卅语源码快照）复制进
   `live/config/includes.chroot/usr/local/src/sahou` —— 它会原样进入构建环境。
3. **chroot 引导**：debootstrap 拉起 Debian 13 最小系统，按
   `package-lists/shanhe.list.chroot` 安装全部软件包（KDE、Wine、Go、NVIDIA 工具、
   输入法……）。
4. **钩子注入**（详见 docs/架构设计.md §4）：编译卅语、部署 IDE、落地 Win11 主题、
   配置 Wine 中文字体、瘦身。
5. **打包**：squashfs 压缩系统 → xorriso 生成 iso-hybrid（BIOS+UEFI 双引导，
   GRUB 菜单已中文化）。

## 进阶：使用 torvalds/linux 主线内核

Debian 默认内核稳定、驱动全。要跟进上游最新内核（新硬件、新特性）：

```bash
sudo bash build-kernel.sh          # 浅克隆主线 + 编译 deb（1~2 小时）
# 把产出的 linux-image-*.deb 装入山河Linux 后重启即可
```

脚本细节见 `build-kernel.sh` 头部注释。
