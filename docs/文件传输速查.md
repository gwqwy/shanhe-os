# 文件传输速查（Windows ⇆ 构建机）

> 场景：Windows（`E:\文件\编程文件\系统\shanhe-os`）⇆ 构建机（Ubuntu 虚拟机）。
> 把下面命令里的 **`用户名`** 和 **`构建机IP`** 换成实际值（构建机里 `ip a` 查看 ens33 的地址）。
> 在 Windows 侧用 **Git Bash** 执行；构建机侧直接开终端。

---

## 〇、一次性准备（构建机里执行）

```bash
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
ip a        # 记下 ens33 的 inet 地址，例如 192.168.xxx.128
```

---

## 一、推送（Windows → 构建机）

### 整个项目（首次或大改后）

```bash
scp -r "E:\文件\编程文件\系统\shanhe-os" 用户名@构建机IP:~/
```

### 单个文件（日常修完即推，最常用）

```bash
# 模板：scp "Windows源文件" 用户名@构建机IP:~/shanhe-os/相对路径/
scp "E:\文件\编程文件\系统\shanhe-os\build.sh" 用户名@构建机IP:~/shanhe-os/
```

### 近期改动的文件对照表（推哪条点哪条）

| 改了什么 | 推送命令 |
|---|---|
| 构建脚本 | `scp "E:\…\shanhe-os\build.sh" 用户名@构建机IP:~/shanhe-os/` |
| 镜像/构建配置 | `scp "E:\…\shanhe-os\live\auto\config" 用户名@构建机IP:~/shanhe-os/live/auto/` |
| 软件包清单 | `scp "E:\…\shanhe-os\live\config\package-lists\shanhe.list.chroot" 用户名@构建机IP:~/shanhe-os/live/config/package-lists/` |
| 构建钩子（单个） | `scp "E:\…\shanhe-os\live\config\hooks\0030-theme.hook.chroot" 用户名@构建机IP:~/shanhe-os/live/config/hooks/` |
| 钩子（全部） | `scp "E:\…\shanhe-os\live\config\hooks\"* 用户名@构建机IP:~/shanhe-os/live/config/hooks/` |
| 编辑器本体 | `scp "E:\…\shanhe-os\live\config\includes.chroot\opt\shanhe-studio\shanhe-studio.py" 用户名@构建机IP:~/shanhe-os/live/config/includes.chroot/opt/shanhe-studio/` |
| 编辑器启动器 | `scp "E:\…\shanhe-os\live\config\includes.chroot\usr\local\bin\sahou-studio" 用户名@构建机IP:~/shanhe-os/live/config/includes.chroot/usr/local/bin/` |
| 语法高亮定义 | `scp "E:\…\shanhe-os\live\config\includes.chroot\usr\share\gtksourceview-4\language-specs\sahou.lang" 用户名@构建机IP:~/shanhe-os/live/config/includes.chroot/usr/share/gtksourceview-4/language-specs/` |

> 上表中 `"E:\…\shanhe-os"` 是 `"E:\文件\编程文件\系统\shanhe-os"` 的缩写，实际执行时写全路径。

推完之后构建：

```bash
cd ~/shanhe-os && sudo bash build.sh
```

## 二、拉取（构建机 → Windows）

### 构建产物 ISO（构建成功后）

```bash
scp 用户名@构建机IP:~/shanhe-os/山河Linux-1.0-amd64.iso "E:\文件\编程文件\系统\shanhe-os\"
```

### 拉日志排查问题

```bash
# debootstrap 日志
scp 用户名@构建机IP:~/shanhe-os/live/chroot/debootstrap/debootstrap.log "E:\文件\编程文件\系统\"
# 构建全程日志（推荐，直接把整个构建输出落盘）
#   构建机上：sudo bash build.sh 2>&1 | tee build.log
#   然后：    scp 用户名@构建机IP:~/shanhe-os/build.log "E:\文件\编程文件\系统\"
```

### 拉整个目录（加 -r）

```bash
scp -r 用户名@构建机IP:~/shanhe-os/docs "E:\文件\编程文件\系统\shanhe-os\"
```

## 三、备选方法

### HTTP 中转（构建机没装 SSH 时）

Windows 侧：

```bash
cd "E:\文件\编程文件\系统"
tar czf shanhe-os.tar.gz shanhe-os
py -m http.server 8000
# 再开一个 Git Bash 执行 ipconfig，记下「VMware Network Adapter VMnet8」的 IPv4，一般是 192.168.xxx.1
```

构建机侧（推送方向）：

```bash
wget http://192.168.xxx.1:8000/shanhe-os.tar.gz
tar xzf shanhe-os.tar.gz
```

拉取方向（构建机上开服务，Windows 取）：

```bash
# 构建机：
cd ~/shanhe-os && sudo python3 -m http.server 8000
# Windows：
curl -O http://构建机IP:8000/山河Linux-1.0-amd64.iso
```

用完 Ctrl+C 关服务。

### VMware 共享文件夹

虚拟机设置 → 选项 → 共享文件夹 → 启用，添加 `E:\文件\编程文件\系统`；构建机装
`sudo apt install -y open-vm-tools` 后，从 `/mnt/hgfs/系统/shanhe-os` 直接 `cp`。

## 四、小技巧

- **先删再传更干净**：整包重传前在构建机 `rm -rf ~/shanhe-os`，避免新旧文件混杂。
- **传完核对**：`ls -l ~/shanhe-os/build.sh` 看时间戳是否刚更新，防止推错目录。
- **构建留日志**：养成 `sudo bash build.sh 2>&1 | tee build.log` 的习惯，报错随时可回溯。
- **不要传进 ~/公共**：那是系统"公共文件"目录，统一用 `~/shanhe-os`。
